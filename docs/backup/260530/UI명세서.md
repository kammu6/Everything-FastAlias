## 🎨 1. UI/UX 최종 기능 명세서 (Everything FastAlias)

### 📌 레이아웃 개요

- **전체 윈도우 크기:** $1200 \times 850$ (픽셀, 창 조절 및 내부 3:7 패널 드래그 리사이징 지원)
- **테마:** 'Slate-50 기반의 클린 라이트 테마' (흔한 흔한 블루/인디고 계열을 탈피할 것)

### [1] 상단 레이아웃 (Slim Integrated Header)

#### ◽ SECTION A: 타이틀, 창제어 컴포넌트, 메뉴바

- **좌측 영역:** 앱 대형 로고 타이틀 (`Everything FastAlias`) 및

- **우측 영역:** 창 제어 버튼 컴포넌트 `[ ─ ] [ ⬜ ] [ ✕ ]` 배치

#### ◽ SECTION B: 타이틀, 창제어 컴포넌트, 메뉴바

인라인 가로형 메뉴바 `[파일] [도구] [도움말]` 배치

- `[파일]` 메뉴 클릭 시 새창 띄우기, 내보내기(결색결과 -> TXT파일), 시스템트레이 ON/OFF, 시작프로그램 등록 ON/OFF, 종료

- `[도구]` 메뉴 클릭 시 **[매핑 테이블 관리자]** 독립 모달 인터페이스 호출.

- `[도움말]` 메뉴 클릭시 **[검색 문법]**, **[정규식 문법]** 독립 모달 인터페이스 호출.

#### ◽ SECTION C: 실시간 검색 엔진

- **검색어 입력창:** 큰 폰트 크기의 텍스트 인풋 박스. 우측 끝에 `[X]`(전체 지우기) 및 실시간 FastAlias 매핑 상태를 나타내는 인디케이터 아이콘 표기.
- **단어 제외 입력창:** 입력된 단어를 최종 쿼리에서 `!<단어>` 형태로 자동 제외.
- **폴더 입력창:** 입력된 직계 경로 매칭에서만 검색(다수의 경로 매핑 로직 필요). `<절대경로A|절대경로B>`

- **FastAlias 메인 스위치:** 검색창 바로 하단에 배치되는 대형 토글 스위치.
  - `ON (Purple)`: 입력어 자동 변환 가동 (사과 ➔ `<사과|apple>`)
  - `OFF (Slate)`: 입력어 가공 없이 엔진 원본 전달

### [2] 좌측 레이아웃 (스마트 쿼리 컨트롤러 - 30%)

> 스플릿 경계선을 마우스 드래그하여 실시간 너비 조절 가능, 최소 너비 320px 제한. 내부 스크롤바 바인딩.

#### ◽ SECTION A: 하단 액션 바

- **`[ 조건 초기화 ]`** 버튼: 좌측 컨트롤러의 모든 세팅 및 검색창을 공장 초기화 상태로 복원하는 Wide Slate 버튼.

#### ◽ SECTION B: 대상 탐색 범위 (Mutually Exclusive Radio Group)

- 가로형 세그먼트 버튼 구조 (하나를 클릭하면 다른 것은 자동 해제)
- `[ 전체 ]` (Default) / `[ 파일만 ]` / `[ 폴더만 ]`

#### ◽ SECTION C: 프리셋 미디어 필터 (Multi-Select Group)

- 칩 버턴 형태로 다중 선택 가능. '전체' 선택 시 타 필터 자동 해제.
- `[ 전체 (Default) ]` `[ 영상 ]` `[ 음악 ]` `[ 사진 ]`
- `[ 문서 ]` `[ 코드 ]` `[ 실행 ]`,`[ 압축 ]`
  - ts확장자는 코드(typescript)와 영상(.ts)파일 모두 포함되어야 함.
  - .m3u8도 영상 필터에 포함되어야 함.
  - `실행`이란 실행파일을 의미함.

- **커스텀 확장자 인풋 필드:** 미디어 프리셋 하단에 배치. 사용자가 `zip;7z;rar` 형태로 수동 제약 가능.

#### ◽ SECTION D: 파일 크기 필터

- **크기 필터 범위:** `[ 최소 크기 인풋 ] ~ [ 최대 크기 인풋 ]` `[초기화]`
- **단위 선택 버튼 구조:** `[KB]`, `[MB]`, `[GB]`

#### ◽ SECTION E: 토글 옵션 그룹 (Grid 2x2 Layout)

- 공간 효율성을 위해 아이콘과 텍스트가 결합된 클릭형 컴팩트 토글 칩(Chip) 버튼 배치.
- `대소문자 구분` (Default: OFF)

- `전체 단어 일치` (Default: OFF)

- `정규식 검색` (Default: OFF)

- `휴지통(Recycle) 포함` (Default: OFF) ➔ OFF 시 쿼리 끝에 `!$Recycle.Bin` 강제 삽입

### [3] 우측 레이아웃 (데이터 그리드 패널 - 70%)

- **검색 결과 테이블 (Virtualized List 기술 적용):** Everything 특성상 수십만 건의 행이 출력되어도 스크롤 멈춤이 없도록 화면에 보이는 영역만 렌더링하는 초고속 그리드 뷰 구현.
- **정렬 가능 테이블 헤더:**
- 각 열 크기 드래그 조절 및 열 순서 좌우 드래그 이동(Reorder) 가능.
- 헤더 셀 클릭 시 오름차순/내림차순 토글 정렬 화살표 인터페이스 표기.
- 구성 요소: `이름`, `경로`, `수정한 날짜`, `크기`, `확장자`

---

### [4] 하단 레이아웃 (System Status Bar)

- **좌측 영역:** 실시간 감지 상태 메시지 출력 (예: `Everything 서비스 활성화 완료 | 매핑 테이블 규칙: 142개 로드됨`)
- **우측 영역:** 조회 데이터 카운터 인디케이터 (예: `선택 항목: 1 / 검색 결과: 4,129개 항목`)

---

### [5] 독립 모달 인터페이스 (Modal Layer)

#### ◽ 모달 A: 도움말 및 문법 가이드

- 제공된 `Everything검색문법.txt`, `Everything정규식문법.txt` 파일의 핵심 상용구와 와이드카드 매뉴얼을 탭 레이아웃(기본 문법/정규식/팁)으로 정형화하여 가독성 있게 파싱하여 보여주는 오프라인 뷰어 팝업 창.

#### ◽ 모달 B: 스마트 매핑 테이블 관리자 (Alias Manager)

- **상단 제어 인터페이스:** `[ 엑셀 파일 가져오기 (.xlsx) ]` 버튼 및 `[ 양식 다운로드 ]` 링크 제공.
- **메인 테이블 편집기:** `[ 원본 단어 ] ➔ [ 변환 단어 목록 (쉼표 또는 세미콜론 구분) ]`을 수동으로 행 추가(`+`), 삭제(`✕`)할 수 있는 정렬 가능한 데이터 시트 UI 제공. 수정 즉시 내부 SQLite DB에 트랜잭션 단위로 영구 커밋 처리.

## 🛠️ 2. 핵심 옵션 기능별 Everything 엔진 매핑 명세

사용자님이 나열한 옵션들은 UI 토글 상태에 따라 백엔드(`QueryTransformer.ts`)에서 최종 쿼리 문자열에 변경자(Modifier)를 추가하거나, `Everything64.dll` API 스위치 함수를 제어하는 방식으로 매핑됩니다.

| 번호  | UI 옵션 기능         | Everything 엔진 매핑 방식                  | 관련 문법 및 API   |
| ----- | -------------------- | ------------------------------------------ | ------------------ | ------------ |
| **1** | **FastAlias On/Off** | 앱 자체 메모리 `Map` 치환 활성화 여부 결정 | <br>**On:** `<사과 | apple>` 생성 |

<br>

<br>**Off:** `사과` 원본 전송 |
| **2** | **정규식 사용** | 쿼리 내 정규식 기호 활성화 제어 | API: `Everything_SetRegex(true)` 또는 변환 쿼리 앞에 `regex:` 적용

|
| **3** | **대소문자 구분** | 영문 텍스트 대소문자 일치 체크 | API: `Everything_SetMatchCase(true)` 또는 `case:` / `nocase:` 적용

|
| **4** | **전체 단어 일치** | 단어의 부분 일치가 아닌 완전한 단어 단위 매칭 | API: `Everything_SetMatchWholeWord(true)` 또는 `wholeword:` 적용

|
| **5** | **단어 제외** | 특정 단어가 들어간 대상 필터링 | 제외할 단어 앞에 `!` 연산자 삽입 (예: `!tmp`)

|
| **6** | **조회 대상 매칭** | 파일명 또는 경로 기준 탐색 범위 지정 | <br>**파일명만:** `nopath:` 적용

<br>

<br>**전체경로 포함:** `path:` 적용

|
| **7** | **확장자 지정** | 특정 확장자 다중 제한 | <br>`ext:` 문법과 세미콜론 사용 (예: `ext:txt;log;md`)

|
| **8** | **확장자별 필터** | 매뉴얼 내 정의된 미디어 상용구 자동 변환 | <br>`video:`, `audio:`, `pic:`, `doc:` 매칭 문법 문자열 끝에 추가

|
| **9** | **하위폴더 재귀 포함** | 검색 경로 지정 시 직계 하위만 볼지 여부 | <br>**On(기본값):** 전체 하위 탐색<br>

<br>**Off(직계만):** 쿼리 대상을 `infolder:` 또는 `parent:` 문법으로 래핑


---

요청하신 **MVVM 패턴**, **SoC(관심사 분리)**, **DRY(중복 방지)**, 그리고 **One Class/Component Per File(1파일 1클래스/컴포넌트)** 원칙을 엄격하게 적용하여 설계한 `frontend` 영역의 상세 폴더 및 파일 구조 가이드라인입니다.

이 구조는 안티그래비티(Antigravity) IDE의 AI 에이전트가 코드를 오독하지 않고 조립할 수 있도록 뷰(UI)와 비즈니스 로직(ViewModel), 데이터 서비스(Model 통신)를 파일 단위로 완전히 쪼개어 배치했습니다.

## ⚙️ 아키텍처 핵심 규칙 및 AI 에이전트 가이드

> **🤖 안티그래비티 바이브 코딩용 프론트엔드 제약 사항**
> 1. **Strict SoC (관심사 분리):**
> * `views/` 폴더 내의 파일은 오직 UI 레이아웃, 스타일(Tailwind), 사용자 입력 이벤트 매핑만 담당하며 **내부 비즈니스 계산 로직을 직접 구현해서는 안 됨.**
> * 모든 데이터 조작, 상태 전이, 비동기 호출 트리거는 연결된 `viewmodels/`의 상태 값과 핸들러를 바인딩하여 처리할 것.
> 
> 
> 2. **One Component Per File (1파일 1컴포넌트):**
> * 예를 들어 좌측 사이드바 전체를 `ControlSidebar.tsx` 하나에 누적하여 코딩하지 말고, `SearchInputGroup.tsx`, `OptionGrid.tsx` 등으로 완벽히 쪼갠 후 `ControlSidebar.tsx`에서는 조합(Composition)만 수행할 것. 이를 통해 코드 가독성을 극대화하고 AI의 컨텍스트 한계로 인한 소스 유실을 방지함.
> 
> 
> 3. **DRY (중복 제거):**
> * 동일한 다크 테마 디자인이 적용되는 토글 스위치, 버튼, 입력창 등은 반드시 `components/` 폴더에 제네릭한 컴포넌트로 한 번만 선언한 뒤 각 뷰에서 속성(`props`)을 통해 수입하여 사용할 것.
> 
> 
> 4. **Everything 특화 Virtualized Table:**
> * `ResultTableBody.tsx` 구현 시 Everything 엔진의 특성상 수만 건의 파일이 1초 안에 조회되므로, 무거운 기본 DOM 매핑을 금지하고 반드시 화면 영역 내 행만 계산하여 노출하는 가상 스크롤(Virtual Scrolling)을 적용하도록 코딩할 것.
