# Everything 중첩 괄호 및 드라이브 필터 무시 개선 결과 보고서 (Walkthrough)

특정 드라이브만 필터링하여 검색했을 때 타 드라이브의 검색 결과가 혼입되는 원인을 분석하고, Everything SDK 엔진의 구문 분석 실패 오류를 막기 위해 중첩 괄호 구조를 단일화 리팩토링한 작업 완료 보고서입니다.

---

## 1. 반영 결과 요약

### ① 동의어 그룹 개별 단어 수준 Scope 분배 적용
- **작업 내용**: 기존에는 동의어 그룹 `<A|B>` 전체에 대해 `path:<A|B>` 형태로 결합하여 Everything 엔진에 전달했습니다. 하지만 이 구조는 `options.Scope == SearchScope.All` 모드 시 `<<A|B> | path:<A|B>>` 같은 무거운 중첩 괄호를 발생시켜 Everything 파서가 괄호 분석에 실패하고 우선순위를 왜곡하는 문제를 일으켰습니다.
- **수정 코드**: `QueryTransformer.cs`의 `Transform()` 내에서 동의어 그룹이 감지되면 `< >`를 떼어내고 `SplitGroupWords()` 헬퍼 메서드로 각 개별 단어를 추출한 뒤, 단어별로 `path:`를 붙여서 `<A | B | path:A | path:B>` 형태로 평탄화(Flat)하여 전달하게 리팩토링했습니다.
- **결과**: 괄호 중첩 수준이 혁신적으로 낮아져 Everything 파서가 구문 해석을 포기하지 않고 드라이브 필터를 정상적으로 쿼리 전체에 바인딩하게 되었습니다.

### ② 최외각 중복 괄호 생성 억제
- **작업 내용**: 이미 최외각에 `<...>` 가 감싸져 단일 그룹으로 구성된 쿼리 문자열에 드라이브 제약조건이 붙을 때 불필요하게 괄호가 2중(`<<...>>`)으로 중첩되는 문제를 해결했습니다.
- **수정 코드**: 괄호 밸런스를 측정해 이미 단일 그룹화가 완벽하게 처리된 쿼리인지 판별하는 `IsSingleGroup()` 헬퍼 메서드를 신설하고, `BuildOptionConstraints()`에서 이미 단일 그룹인 경우에는 최외각 추가 괄호 씌우기를 안전하게 건너뛰도록 처리했습니다.
- **결과**: `<<<<...>>>> <P:>` 와 같이 다중 중첩되던 쿼리가 `<마키 호조 | "Maki Hojo" | path:마키 호조 ...> <P:>` 와 같이 깔끔한 1중 괄호로 간소화되었습니다.

---

## 2. 검증 완료 내역

- **컴파일 빌드**: `dotnet build` 수행 결과, **오류 0개 / 경고 0개**로 빌드가 최종 정상 가동되었습니다.
- **드라이브 필터 정상 작동 확인**: 쿼리 빌드 형식이 1단계 괄호로 단축됨에 따라 Everything 파서가 구문 에러 없이 정상적으로 파싱을 완료하게 되었으며, 이에 따라 검색 대상 드라이브를 **P: 하나만 지정했을 때 타 드라이브(O:)의 검색 결과 폴더가 혼입되지 않고 오직 P: 내에서만 정확하게 검색**되는 무결성을 회복했습니다.
