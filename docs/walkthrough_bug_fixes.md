# Everything 검색 엔진 파서 누수 버그 및 안정성 개선 결과

## 1. 드라이브 필터 누수(Scope Leak) 버그 완벽 해결
사용자께서 제보해주신 **"P: 드라이브만 선택했는데 O: 드라이브의 폴더가 조회되는 현상"**의 근본 원인을 파악하고 완벽히 수정했습니다.

### 원인 분석: 매크로 수식어 우선순위 및 그룹화 문법 오해
- Everything 엔진 공식 매뉴얼에 따르면, 1.4 버전 기준 **`()` 소괄호는 일반 텍스트(리터럴)로 간주**되며, **`< >` 꺾쇠 괄호가 공식 검색조건 묶기(그룹화) 연산자**입니다.
- 이전 픽스에서 `(...)`를 사용했을 때 일부 결과가 제대로 나오지 않거나 유출된 이유는, `()`가 그룹화 연산자로 작동하지 않고 실제 파일 이름에 괄호 문자가 포함된 파일만 억지로 교집합 검색했기 때문이었습니다.
- 그룹화가 풀린 상태로 전송된 쿼리 `A | B folder: <P:>`는 `A OR (B AND folder: AND P:)`로 오해석되어, 앞선 'A' 조건에 해당하는 결과들이 드라이브/폴더 제약을 무시하고 O드라이브 등에서 대량으로 유출되었습니다.

### 해결 로직: 각 OR 개별 키워드 단위 수식어 부착 및 드라이브 path 명시
- Everything 엔진에서 수식어(modifier, 예: `folder:`)는 `|` (OR) 연산자를 만나면 그 스코프가 끊어집니다. 따라서 `<folder:A | B>`는 B에 대해 `folder:` 제한이 걸리지 않고 파일까지 검색에 걸리는 누수가 발생합니다.
- 이를 해결하기 위해 `QueryTransformer.cs` 내부의 `ApplyModifierToEachTerm()` 메소드가 `TokenRegex`를 이용하여 전체 쿼리를 토큰화한 후, 각 OR 그룹 내의 개별 단어 단위마다 명시적으로 `folder:` 수식어를 분배하도록 설계했습니다.
  - 예: `<folder:사과 | folder:apple | folder:🍎>`와 같이 모든 동의어/별칭 키워드에 개별적으로 `folder:`가 보장됩니다.
- 또한 검색 드라이브 범위 지정 시에도 단순 드라이브 문자(`P:`)가 아닌 공식 변경자인 `path:P:\` 형태로 쿼리에 명시하여 다른 드라이브로의 결과 유출을 완벽히 통제했습니다.
- 개선 이후 단위 테스트(`Test_FolderPreset_With_FastAlias_And_OR` 포함)를 추가 및 작동하여 모든 테스트가 통과함을 확인했습니다.

## 2. DB I/O 성능 병목(저장 오버헤드) 해결
### 원인 및 증상
- 기존에는 사용자가 검색어를 한 글자 입력하거나 옵션을 클릭할 때마다 `TriggerSearch`가 호출되며 무조건 `SaveSettings()`를 통해 SQLite DB에 UPDATE 쿼리를 날렸습니다. 이로 인해 불필요한 디스크 I/O가 대량 발생했습니다.

### 해결 로직
- `SearchViewModel.cs` 내의 즉각적인 UI 업데이트(Debounce 타이머 시작) 역할만을 담당하는 `TriggerSearchOnly()` 메서드를 분리했습니다.
- 체크박스 토글 등 상태 변경 시에는 `TriggerSearchOnly()`를 호출하여 UI 멈춤 없이 검색 타이머만 가동합니다.
- 실제 `EverythingBridge.Search` 비동기 검색이 실행되기 직전(`ExecuteSearchAsync`)에만 **단 1회** DB에 일괄 저장(`SaveSettings()`)하도록 스레드/비동기 아키텍처를 최적화했습니다.

## 3. 우클릭 컨텍스트 메뉴 기능 확인
- 요청하신 "열기", "경로 열기", "전체 경로 복사" 기능은 현재 `ShellContextMenu.cs`를 통해 Windows 기본 우클릭 메뉴의 최상단에 주입되도록 구현되어 있습니다. 
- 테스트를 통해 해당 메뉴가 정상적으로 표시되는지 확인 부탁드리며, 만약 속도 문제나 표시 오류가 있다면 WPF 네이티브 `ContextMenu`로 즉시 교체해 드리겠습니다.
